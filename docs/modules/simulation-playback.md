# Simulation Playback

## Current Capability

Step 3 plays simulation rounds against one ledger-backed Timeline V2. The 2D graph and geographic map consume the same ordered events, but they use separate geometry renderers: the 2D graph preserves semantic/network structure, while the map only renders evidence-backed spatial placement and paths.

Playback uses the network committed at the current round watermark as a stable, low-emphasis base plus a transient source → path → target wave. That committed base is never rebuilt or hidden between animation ticks; structures whose `first_seen_round` is still in the future remain genuinely hidden. Completed paths remain as a quiet current-round trail, while only events whose timing window is currently active receive the primary propagation focus.

The compact playback bar shows only the current progress rail, percentage, and one play/pause action. Connection deltas and new or active relationships belong to the observation views below, where they have enough room to be read. The Agent workbench and relationships/risk view consume the same append-only action, state, policy, relationship, and emergence artifacts as the round snapshot; they are not post-hoc UI narratives.

## Key Rules

- Runtime intervention text follows `docs/modules/semantic-input.md`. `/api/simulation/inject` resolves natural-language targets against the current catalog before writing runtime state, preserves an explicit `start_round=0`, and uses a persisted per-draft idempotency receipt so retries cannot duplicate a runtime mutation.
- Accepted normalized interventions enter the activity/history list directly. Model, repair, fallback, and unresolved-target details stay in semantic audit and system logs.
- The global workflow shell owns the Step 3 title and run status. Step 3 must not repeat them as a local hero or as cards for round, stage, scenario state, or simulated time.
- Runtime playback is one compact row: a single progress rail, one percentage, and one play/pause button. The rail already supports direct scrubbing, so previous/next/latest buttons are not separate controls.
- Playback delay and the state-heat sorting key are implementation defaults, not user decisions. Do not expose millisecond speed or a generic “state dimension” selector in the playback bar.
- The compact playback row and observation tabs remain visible above the independently scrolling workspace. Their combined height should stay below 120 px in the standard split workbench.
- Cross-step actions remain in the shared compact bottom action bar. Runtime intervention stays a scoped action there and opens its drawer without enlarging the playback row.
- Visible round labels, distance bands, uncertainty labels, status messages, and intervention results must use the shared Chinese display boundary. Unknown enums, numeric-only identifiers, exception text, paths, and network addresses are not valid display fallbacks.
- Start, stop, inject, status, configuration, action, and timeline JSON responses share the same backend response boundary. Runtime control failures may keep machine error codes, but their visible message is Chinese and never includes traceback or raw exception detail.
- Step 3 has five peer observation views: runtime pulse, state and action, diffusion and feedback, agent workbench, and relationships and risk. Do not merge them back into a single long overview.
- Every runtime round follows one fixed order: activate due Agents; apply variables and diffusion; validate and execute Agent actions; update relationship coupling and mechanism propagation; execute policies; calculate feedback; detect Agent emergence; persist the round snapshot; then detect and refresh risks. Risk results must never be fed back into the earlier Agent decision stages.
- Agent actions must pass capability, permission, resource, lifecycle, and prerequisite checks. Proposed but rejected actions remain visible as audit outcomes and produce no unauthorized state delta.
- Relationship state changes only through recorded interaction evidence. The runtime stores trust, dependency, coordination, and tension plus the `RelationshipEvent` that explains each change; co-location or a shared risk reference alone is insufficient.
- Runtime Agent emergence resolves capability gaps in the order dormant activation, aggregate split, then provisional creation. New or split Agents become actionable from the next round, and all activation, creation, lineage, and candidate outcomes remain append-only.
- Policy execution consumes the prepared `PolicyExecutionPlan`. A policy without a qualified executor or satisfied trigger remains pending/unbound; it must not create an execution result merely because the user entered a policy intent.
- Runtime intervention is a write operation and lives in a separate drawer with new, active, and historical intervention states. It is not an observation panel.
- System logs are internal diagnostics and must not appear in the normal Step 3 business interface.
- The animation response keeps legacy `frames` for compatibility and adds `timeline.contract_version=simulation-playback-timeline.v2`. Timeline events come from the spread, Agent interaction, dynamic-edge, and relationship-event ledgers before any frame fallback is considered.
- Every V2 timeline event carries a stable ID, global and per-round sequence, phase/kind, source/target references, typed edge references, evidence-backed parent references, deterministic `timing.start_ms` / `timing.duration_ms`, intensity/confidence, grounding, and Simplified-Chinese display fields. `path_edge_ids` is the strictly ordered, directionally continuous route that may be staggered from source to target; `related_edge_ids` contains affected relationships or mechanism/evidence references and never becomes a later route segment. `edge_ids` remains only the ordered compatibility union of those disjoint fields. Explicit, resolvable ledger ancestry may additionally expose `root_event_id` and `hop`; unresolved roots are not projected. Missing ledgers remain explicit in timeline grounding.
- Live cursor reads use a non-negative `after_cursor` or `since_cursor`. Only completed rounds enter the live timeline, layout history, and frame inputs, so an emitted sequence never shifts and an unfinished round cannot expose phantom relationships. Cursor responses omit historical frames; an empty window also omits layout. Frozen/legacy artifacts may expose `legacy_frame`, but it is marked `legacy_fallback`; a live run waiting for its first committed ledger keeps cursor `0`, and Agent numeric IDs are never used as propagation order.
- A ledger-provided single main relationship (`edge_id`, `relationship_edge_id`, or `relationship_contract_id`) is authoritative and may form one path segment only when it resolves between the event source and target; it must not expand into every parallel source-target edge. Explicit multi-edge paths must pass directional continuity. Diffusion events without an explicit edge prefer one matching transport edge over a generic neighbor relation. Mechanism edges and other supporting references remain `related_edge_ids`: they may stay visible as subdued context but are never staggered as propagation. Untyped ledger or legacy `edge_ids` is path-compatible only when it contains one edge or declares an ordered-path contract; an untyped multi-edge set remains related evidence. Persisted V2 paths are revalidated against the current layout before playback, so a stale or directionally broken path is demoted to related evidence instead of being staggered. A legacy interaction that proves only its endpoint pair chooses one stable candidate path and marks ambiguous matches `partial`, rather than animating every parallel edge. Historical dynamic edges referenced by committed timeline events stay in the animation layout after dormancy or expiry, without being reactivated in current runtime state.
- Parent links are projected only from persisted causal references. The current ledgers do not consistently write a cross-stage `root_event_id` or `hop`, so Timeline V2 currently guarantees deterministic phase waves, not a complete causal tree; the projection layer must not invent missing ancestry from timestamps, shared endpoints, or visual proximity.
- The Wuhan frozen fixture is an explicit exception only for its curated environment-diffusion source data: it deterministically projects the existing Jianghan outbreak variable over configured directed transport edges and cumulative travel times. These events are labeled `golden_fixture_projection` / `curated_deterministic_fixture`, never `observed`, and do not make Agent responses causal children.
- Playback frame changes must not rebuild the 2D graph when the node and edge structure is unchanged.
- User zoom, pan, and drag state on the graph must remain usable while the animation is playing.
- The base graph should stay spatially stable; frame changes should update visual state and focus highlighting only.
- 2D semantic zoom is clamped to `0.5–5`. Below `0.7`, ordinary Agent labels enter level-of-detail hiding; active sources/targets, selected nodes, risk nodes, regions, and priority nodes remain readable. Node glyphs and text do not scale as one SVG image.
- The 2D density modes cap and score baseline relationships by evidence, confidence, strength, broad node coverage, and per-node fan-out. Parallel same-semantic relationships are bundled. The active propagation overlay is independent of that baseline cap, so a real current event cannot disappear because its edge was outside the initial top-N.
- 2D Agents stay constrained around their owning region. Intra-region Agent links use compact distances; cross-region propagation remains visible as a deliberate cluster-to-cluster jump instead of turning local interactions into full-screen lines.
- Timeline playback keeps the full event ledger for audit but renders at most 18 readable event paths per frame and at most 6 simultaneous current-wave events. Both dense-frame sampling and the current-wave cap preserve phase diversity; active events are selected round-robin by phase so a still-running environment front cannot disappear merely because later Agent or relationship events start.
- The Step 3 pulse ledger and the graph/map wave consume the same `propagation_events` and active IDs. The business panel must not report a non-zero current wave while the visual surface is still using an unrelated legacy focus set.
- A target node must not enter focus when its event merely starts. The source may pulse first, the ordered path then grows, and the target becomes focused only in the arrival/response phase; this keeps the visual order causal instead of lighting both endpoints before the route is traversed.
- A short gap between waves keeps only the low-emphasis base network; it must not relight the last completed event as though it were still active.
- The map uses fractional cursor-anchored wheel zoom with a request-animation-frame easing loop. It does not use Leaflet's integer/debounced pulse zoom. Animation-layer reconciliation must preserve the user's current zoom and center; content fitting is allowed only for initial content or an explicit projection identity change.
- The Leaflet external-viewport watcher compares a primitive latitude/longitude/zoom signature, not projection-object identity. Per-frame animation projection replacement therefore cannot reset a user-controlled fractional zoom, including across round changes.
- The animation `layout` preserves the source map projection's `source_mode`, `map_seed_id`, `geographic_grounding`, `data_quality`, `selection_summary`, and `meta`. Step 3 must carry those fields through its animation-map adapter, including an explicit null seed ID, rather than recreating an ungrounded map DTO from coordinates alone.
- Map overlays reconcile by stable feature ID instead of clearing and recreating every layer on each animation frame.
- A map relationship uses supplied LineString/MultiLineString/route geometry when available. With only two real geographic endpoints it uses one honest straight segment; the renderer must not invent random bend points or polygon-like detours.
- Synthetic Agent and mixed synthetic/geographic relationships are omitted from physical propagation on the map. A synthetic region-to-region relationship may appear only as a muted dashed schematic and cannot receive the primary physical wave treatment.
- `curated_deterministic_fixture` is a narrow replay-only spatial grounding, not an alias for real or map-seed geography. Its primary map wave is allowed only when both nodes explicitly carry finite fixture coordinates and the referenced edge is an explicitly fixture-grounded `transport_edge`; other fixture relationships remain schematic or omitted.
- Steady items already committed at the current watermark remain visible at low emphasis during Timeline V2 playback. Backend `hidden` and `first_seen_round > current_round` remain invisible in both 2D and map renderers, even if a stale focus/highlight reference names them; `hidden` must not be promoted to `steady` or `faded` merely to preserve context between waves.
- Graph inspection state obeys the same watermark. When scrubbing backwards, a selected node, edge, parallel-edge group, or self-loop group is reconciled against the current projected graph; if every selected entity is absent or `hidden`, its label emphasis and detail panel are cleared before rendering.
- Step 3 should prefer the animation payload layout while replaying frames so node and edge IDs match the frame state contract.
- Replay playback stops at the last frame. It should not loop back to the first frame automatically, because that reads as a sudden refresh.
- Route changes and component unmounts do not stop a backend run. Only the explicit stop operation may terminate it, so users can leave Step 3 and return without losing an in-progress simulation.
- Wuhan frozen replay and normal generated simulations must use the same Step 3 playback behavior.
- Step 3 reuses the immutable V2 definitions from Step 2. Selecting a risk changes only the local viewing focus and highlights its real mechanism nodes/edges; selection must not change simulation state or Agent behavior.
- Risk focus may highlight every referenced mechanism node and edge in the relationship graph, but the map renders only references with real geographic anchors. Playback must not synthesize coordinates for process, evidence, family, color, or other non-geographic nodes.
- The risk view shows the causal statement, dedicated tension trace, runtime status, created round, evidence state, dedicated metrics, emergence/status events, and primary-risk switches. Main families are filters/report groups, not a second visible risk ontology.
- The Agent workbench shows lifecycle, representation level, capabilities, relative resource state, and latest validated action. The relationships/risk view separately shows current relation state, relation events, Agent activation/split/provisional-creation events with effective rounds, and risk observations. It must state the one-way boundary: risk reads outcomes and cannot create Agents.
- Any returned risk collection uses one compact horizontal selector. The panel renders details only for the selected object instead of stacking a vertical card wall above the detail area, and the frontend does not assume the current active-risk cap is a permanent display limit.
- Risk navigation buttons are conditional on actual horizontal overflow. When all objects fit there are no arrow controls; when they do not fit, two small previous/next buttons supplement trackpad, wheel, and touch scrolling. Narrow viewports keep the same rail and never switch to a native dropdown. Empty monitoring, lifecycle, and quality sections stay hidden so they do not reserve blank vertical space.
- Newly emerged risks appear automatically after the runtime detector promotes them. Dormant and resolved definitions remain available as history, while no more than eight risks are active.
- When no active risk remains, `primary_active_risk_id` is empty. A resolved object must not remain primary; if a later snapshot validly returns an object to watch/elevated/critical, primary selection may resume under the normal five-point hysteresis rule.
- A forced rerun first closes the retained command environment, then clears prior round snapshots, actions, risk runtime/events, Agent interactions and decisions, dynamic/relationship events, reasoning, emergence, lineage, candidate runtime ledgers, and injection receipts before round zero. It preserves the prepared immutable V2 definitions and their preparation-time candidate audit. One simulation may have only one live IPC consumer.
- Server shutdown may terminate a lingering child environment after both platforms have emitted their completion records, but it must preserve the successful `completed` run state, completion timestamp, round count, and platform completion flags. Shutdown cleanup marks only genuinely unfinished runs as `stopped`.
- The affected-subject display uses real entity/Agent references and shows the receptor-role match label as provenance. Machine scope keys and primary-region IDs remain available to the client but are translated or omitted from visible text.
- A zero-risk simulation remains a valid playback/report state and shows the evidence-gated empty message instead of a placeholder object.
- On viewports up to 760px, the shared workflow shell shows the Step 3 workbench and graph as separate full-width local views. The graph toggle switches between them without changing the simulation route, selected risk, or runtime state.
- Legacy frozen artifacts may be projected through the V2 compatibility boundary, but the Wuhan fixture is versioned and regenerated whenever the formal animation contract changes so `/demo/wuhan` remains a faithful fast fixture for the shared flow.
- The current Wuhan animation artifact embeds Timeline V2 directly. Its two frozen copies must remain byte-deterministic and must pass event-order, reference-integrity, frame-linkage, and rebuild-hash validation.
- Wuhan validation additionally requires a non-empty `environment_diffusion` phase, one resolvable root-to-multi-hop chain, complete source/target/transport-edge references, parent/root/hop continuity, and in-range arrival rounds derived from each edge's `travel_time_rounds`.
