# Kaleido 工作流界面规范

本文是 Step 1–4 工作台的共享视觉契约。页面可以有不同的数据结构，但不能各自发明颜色、字号、卡片层级或交互密度。

## 主题色

- 主交互色：`--k-color-brand-600`，用于主按钮、当前步骤、进度和明确选中态。
- 深色强调：`--k-color-brand-700`，用于标题、按钮悬停和高优先级文字。
- 淡绿色背景：`--k-color-brand-050` / `--k-color-brand-100`，只用于轻量选中态和状态提示。
- 正文、次要文字、弱文字分别使用 `--k-color-text`、`--k-color-text-secondary`、`--k-color-text-muted`。
- 边框和分隔线使用 `--k-color-border` / `--k-color-border-strong`。
- 工作流业务界面不使用蓝色作为主交互色，不使用蓝色填充 Tag，不以多色渐变区分普通模块。
- `Light / Medium / High / Extra High / Ultra` 是分析强度的固定英文产品词汇，属于明确的界面文案例外；禁止英文泄漏不应把它们自动翻译成中文。

所有颜色定义集中在 `frontend/src/styles/tokens.css`。组件不得复制一套近似色作为新的局部主题。

## 字体与字号

字体统一使用 `--k-font-sans`。机器标识、轮次编号和需要等宽对齐的数字可以使用 `--k-font-mono`。

| 语义角色 | Token | 大小 | 使用范围 |
| --- | --- | --- | --- |
| 紧凑说明 | `--k-text-caption` | 11px | 密集元数据、极短辅助标签；不得承载正文 |
| 辅助信息 | `--k-text-meta` | 12px | 提示、时间、数量标签、Tag |
| 正文 | `--k-text-body` | 13px | 工作台默认正文、表格内容、描述 |
| 操作文字 | `--k-text-ui` | 14px | 按钮、页签、行标题、表单标签 |
| 分区标题 | `--k-text-section` | 16px | 内容分区标题、详情区标题 |
| 页面标题 | `--k-text-title` | 18px | 面板主标题、当前对象标题 |
| 重点结论 | `--k-text-display` | 20px | 每个工作台最多一个主要结论或主标题 |

正文基准必须由每个 Step 的根容器显式设置为 `--k-text-body`，不能依赖浏览器默认 16px。普通卡片或容器不会因为面积大就自动放大文字。数据数量可使用 18px，但必须与同层标题区分，不能与正文竞争。

禁止事项：

- 新增 10px 可见业务文字。
- 用 `clamp()` 把工作台标题放大到 20px 以上。
- 未设置字号，让段落继承浏览器默认 16px。
- 同一语义角色在不同 Step 使用不同字号。
- 为了填满空白而放大文字或数据。

## 行高与字重

- 标题：`--k-leading-tight`，约 1.3。
- 按钮、页签和行标题：`--k-leading-ui`，约 1.4。
- 工作台正文：`--k-leading-body`，约 1.6。
- 正式报告长文：`--k-leading-reading`，约 1.72。
- 正文默认常规字重；只有标题、关键数字、选中态和主操作使用 600–700。

## 容器与层级

- 右侧工作台是一张连续的内容面，不再套一个全高圆角大卡片。
- 大区块主要靠留白、标题和分隔线组织。只有可比较的重复记录可以使用轻量 item surface。
- Tag 使用透明背景和细描边。完整说明不能塞进 Tag；超过一行的内容进入正文、表格行或选中详情。
- 固定底部操作区使用共享 `WorkflowActionBar`，贴底、直角、与内容面相接，不渲染成悬浮圆角容器。

## 大数据密度

- 风险对象较少时直接横向展示；只有真实溢出时才显示左右浏览按钮。
- Ultra 等高强度结果不得一次展开所有详情。横向选择、分页表格、分区详情和按需展开是默认模式。
- Agent、关系和证据列表优先使用表格或行式列表；禁止数百张卡片构成长页面。
- 文本过长时，列表只保留识别信息和一行摘要，完整内容在选中详情中展示。

## 维护与验证

- 共享视觉入口：`frontend/src/styles/tokens.css`。
- 共用组件：`frontend/src/components/ui/`。
- 工作流壳：`frontend/src/components/KaleidoWorkflowShell.vue`。
- 字号变更先修改语义 token 或语义角色映射，禁止在截图对应位置追加一次性覆盖。
- 每次视觉结构调整至少执行前端构建和 `npm run test:display-text`。
- 浏览器验证覆盖 Step 1–4 的所有主页签，记录实际计算字号、页面溢出、可见英文/内部 ID 和窄屏行为；不能只看单张截图。

## 已知风险

历史组件仍保留部分早期局部字号声明。当前通过各 Step 底部的“typography contract”覆盖到共享语义层级；后续编辑这些模块时，应逐步删除被覆盖的旧声明，避免再次形成双重来源。
